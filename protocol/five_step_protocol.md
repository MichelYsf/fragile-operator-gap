# Five-Step Assumption‑Extraction Protocol

This protocol describes how to extract implicit operating‑environment assumptions from normative cybersecurity frameworks.  It is intended to be simple, repeatable and suitable for qualitative systematisation-of-knowledge research.

## Step 1 – Select framework and principle
Choose a cybersecurity framework or regulation and identify a specific normative statement, principle or clause to analyse.  Document the framework title, version, publication date and the exact text of the principle.

## Step 2 – Extract normative language
Parse the selected principle to identify all verbs, modal verbs and requirements.  Capture the directive language exactly as it appears in the source.

## Step 3 – Identify operational assumptions
For each directive, ask: *what must be true in the operator’s environment for this directive to be realistically achievable?*  List these assumptions explicitly.  For example, if the principle mandates continuous monitoring, an implicit assumption is that reliable power and connectivity exist to sustain monitoring infrastructure.

## Step 4 – Map to environmental dimensions
Map each assumption to one of seven environmental dimensions: **Power**, **Connectivity**, **Supply Chain**, **Skilled Labour**, **Legal and Regulatory**, **Financial Resources** and **Physical Security**.  Assign multiple dimensions if necessary.

## Step 5 – Code and record
Record the coded assumption with the framework name, principle identifier, assumption text and mapped dimension(s).  Maintain this coding in a structured dataset (see `taxonomy/49_cells.csv`).  Document any uncertainties and retain the original text for transparency.
